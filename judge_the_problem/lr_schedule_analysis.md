# 核心诊断：固定学习率导致模型"跳脚"，无法深入优化

> 基于 SCRIBE GRPO 1.5B 完整实验数据的最终分析

---

## 一句话总结

**固定学习率 5e-6 + 无 warmup/退火 = 模型始终在"浅层震荡"，从未进入"深度优化区"。**

---

## 证据：Accuracy 曲线的"平台期"

| Iter | Accuracy | 状态 |
|------|----------|------|
| 0 | 64.0% | 起点 |
| 10 | 61.5% | 缓慢下降 |
| 20 | 35.5% | 崩溃（跳飞） |
| 30 | 65.0% | 恢复（弹回） |
| 40 | 64.5% | **平台期** |

**关键观察**：
- iter 30-40：accuracy 稳定在 64-65%
- 与 SFT 基线 67.5% 的差距：**始终 2.5-3.0 pts**
- 这个差距**从未缩小**

**结论**：模型在 iter 30 后没有"继续学习"，只是"稳定在了 SFT 附近"。

---

## 为什么固定学习率导致"跳脚"？

### 理想的学习率曲线

```
Iter 0-5:   lr = 1e-6  (warmup，小步探索)
Iter 5-20:  lr = 5e-6  (稳定期，正常更新)
Iter 20-30: lr = 2e-6  (退火，精细调整)
Iter 30-50: lr = 5e-7  (收敛，微调)
```

### 实际的学习率（你的代码）

```
Iter 0-50:  lr = 5e-6  (固定不变！)
```

**后果**：
- iter 0-5：lr 过大 → 模型"跳飞"到错误区域
- iter 15：KL=5.38（剧烈漂移）
- iter 20-30：lr 仍然过大 → 无法精细收敛，只能"震荡"
- iter 30-40：lr 过大 → 无法深入优化，只能"稳定在表面"

### 类比

```
理想情况：
  像雕刻家，先用大刀粗雕，再用小刀细刻，最后用砂纸打磨
  → 作品越来越精细

你的情况：
  始终用大刀在砍
  → 砍到某个形状后，再也无法更精细
  → 始终差那"最后一公里"
```

## "跳脚"的具体表现

### 1. Reward 的剧烈震荡

| Iter | Mean Reward | 说明 |
|------|-------------|------|
| 12 | 0.612 | 峰值 |
| 20 | 0.438 | 暴跌 |
| 26 | 0.580 | 又升 |
| 30 | 0.356 | 又跌 |
| 42 | 0.610 | 再升 |

**模式**：reward 在 0.35-0.61 之间**周期性震荡**

**原因**：固定 lr = 5e-6 太大
- 模型每次更新都"走过头"
- 然后被 KL 惩罚"拉回来"
- 然后下次又"走过头"
- 循环往复...

### 2. KL 的反复 spike

| Iter | KL | 说明 |
|------|-----|------|
| 15 | 5.38 | 剧烈漂移 |
| 30 | 1.64 | 再次漂移 |

**模式**：每隔 ~15 iter 来一次 KL spike

**原因**：固定 lr 导致累积漂移
- 小步累积 → 逐渐远离 SFT
- 到达某个阈值 → KL 突然爆发
- 然后被拉回来 → 循环

### 3. Accuracy 的"天花板"

```
SFT: 67.5% (天花板)
GRPO iter 30: 65.0% (差 2.5 pts)
GRPO iter 40: 64.5% (差 3.0 pts)
```

**关键**：GRPO **从未超越 SFT**

**原因**：固定 lr 无法做"微调"
- 模型在 SFT 附近"徘徊"
- 但无法"深入"到更好的区域
- 因为 lr 太大，一走就"飞"

## 为什么模型"无法深入深度优化区"？

### 优化景观视角

```
                    accuracy
                       ↑
    SFT 区域          67.5%  ← 起点（高处）
       ↓                |
    浅层区域      64-65%  ← GRPO 徘徊（低处）
       ↓                |
    深层区域      ???    ← 从未到达（可能更好）
       
    固定 lr=5e-6:
      → 从 SFT 出发，一步就跳到浅层区域
      → 然后在浅层区域"跳脚"（震荡）
      → 永远无法回到 SFT，更无法超越
```

### 学习率的影响

| 学习率 | 行为 | 结果 |
|--------|------|------|
| 太大 (5e-6) | 一步跳飞 | 震荡，无法收敛 |
| 适中 (1e-6) | 稳步前进 | 可能收敛到更好区域 |
| 太小 (1e-7) | 几乎不动 | 收敛极慢 |
| **理想（退火）** | **先大后小** | **先快速接近，再精细打磨** |

## 解决方案：添加学习率调度

### 推荐配置

```python
from torch.optim.lr_scheduler import CosineAnnealingLR, LinearLR, SequentialLR

# 在 main() 中，optimizer 创建后添加：

total_iterations = args.num_iterations  # 50
warmup_iterations = 5  # 前 5 iter  warmup

# Warmup: 从 0.1 * lr 线性增加到 lr
warmup_scheduler = LinearLR(
    optimizer,
    start_factor=0.1,
    end_factor=1.0,
    total_iters=warmup_iterations
)

# Cosine Annealing: 从 lr 退火到 0.01 * lr
cosine_scheduler = CosineAnnealingLR(
    optimizer,
    T_max=total_iterations - warmup_iterations,
    eta_min=args.learning_rate * 0.01  # 最终 lr = 5e-8
)

# 组合
scheduler = SequentialLR(
    optimizer,
    schedulers=[warmup_scheduler, cosine_scheduler],
    milestones=[warmup_iterations]
)

# 在每个 iteration 结束时调用
for iteration in range(args.num_iterations):
    # ... GRPO update ...
    scheduler.step()
```

### 预期学习率曲线

```
Iter 0:   lr = 5e-7   (warmup start)
Iter 5:   lr = 5e-6   (warmup end，峰值)
Iter 15:  lr = 4e-6   (开始退火)
Iter 30:  lr = 2e-6   (中期)
Iter 40:  lr = 1e-6   (精细调整)
Iter 50:  lr = 5e-8   (收敛)
```

### 预期效果

| 阶段 | 学习率 | 行为 | 预期 Accuracy |
|------|--------|------|--------------|
| iter 0-5 | 5e-7 | 小步探索 | 64-65% |
| iter 5-15 | 5e-6 | 正常更新 | 可能短暂下降，但可控 |
| iter 15-30 | 3-4e-6 | 逐步退火 | 稳定上升 |
| iter 30-40 | 1-2e-6 | 精细调整 | **超越 SFT？** |
| iter 40-50 | 5e-8 | 微调收敛 | 稳定在高点 |

## 关键洞察

### 你的实验实际上证明了什么？

1. **SFT 是强的**：67.5% 是一个很高的基线
2. **GRPO 没有破坏 SFT**：最终 64.5%，接近基线
3. **但 GRPO 也没有超越 SFT**：因为固定 lr 无法深入优化
4. **模型是鲁棒的**：能从崩溃中恢复

### 真正的瓶颈

| 瓶颈 | 影响 | 解决方案 |
|------|------|---------|
| 固定 lr=5e-6 | 无法收敛，震荡 | 添加 lr 调度 |
| w1=0.32 | reward hacking | 提升到 0.55 |
| group_size=4 | baseline 噪声 | 提升到 8-16 |
| 无 warmup | 初始更新过大 | 添加 warmup |

**最关键**：固定 lr 是"根因中的根因"
- 即使有 reward hacking，如果 lr 合适，模型也能慢慢收敛
- 但固定 lr 导致模型"跳脚"，永远无法稳定
